# Architectural Decisions

| Decision | Choice | Why | Date |
| --- | --- | --- | --- |
| GUI framework | iced 0.13 | Rust-native, wgpu integration via `shader::Program`, no GC | 2026-03-29 |
| GPU rendering | Custom wgpu shader via iced's `shader::Primitive` | Direct control over texture upload, zoom/pan uniforms, and render pass | 2026-03-29 |
| wgpu version | iced's bundled wgpu 0.19 re-export | Using standalone wgpu causes type mismatches with iced's shader traits | 2026-03-29 |
| SVG rendering | resvg | Rasterizes SVG to pixels on CPU, then uploads as texture so it shares the raster pipeline | 2026-03-29 |
| Thumbnail strategy | Decode raster/SVG images directly or prefer embedded RAW thumbnails and previews before resizing to 200px max | Keeps common-format thumbnails simple while making camera RAW thumbnails fast enough for library browsing | 2026-04-19 |
| Thumbnail display | iced `Image` widget with `Handle::from_rgba` | Pre-decoded pixel data avoids iced re-decoding and coexists with shader viewer | 2026-03-29 |
| Dual navigation | `library_index` (library mode) vs `DirNav` (directory mode) | Library browsing and direct file opening are independent use cases | 2026-03-29 |
| Async decoding | `tokio::task::spawn_blocking` | Keeps the UI responsive; iced's tokio feature provides the runtime | 2026-03-29 |
| GPU texture limit | Runtime query in `prepare()`, downscale if exceeded | The limit varies by GPU and cannot be hardcoded | 2026-03-30 |
| RAW decoding | `rawler` with thumbnail/preview-first library decoding and raw-pixel-first detail decoding with embedded-image fallback | Adds broad camera RAW support while keeping the viewer and thumbnail contracts unchanged | 2026-04-19 |
| RAW detail loading | Supersede the earlier raw-pixel-first Detail choice with staged RAW Detail loading: embedded preview first when available, then background full-resolution upgrade plus async EXIF | Improves time-to-first-image in Detail without giving up the higher-quality final RAW path | 2026-04-20 |
| Runtime data directories | Keep `decoded-cache/` and `local-edits/` repo-local (gitignored) during development | Inspectability during development (see lessons 2026-04-20/21); explicitly NOT distribution-ready — both must move to `%LOCALAPPDATA%/photo/` before `photo.exe` ships outside this repo, since the app falls back to no-cache behavior when no repo root is found | 2026-06-10 |
| Offline-source semantics for baked local edits | Fail open to the bake when the source file is ABSENT (metadata unreadable); keep failing closed when the source is PRESENT but its metadata mismatches. Cache keys resolve through reachability-independent candidates (canonical, verbatim `\\?\` guess, raw path) | Sources live on removable camera media; the bake holds exactly the pixels the user last committed, and with no source on disk there is nothing newer to contradict it — while a reachable rewritten source genuinely invalidates the bake. Supersedes the 2026-04-22 unconditional fail-closed validation for the absent-source case only | 2026-06-11 |
| Library membership semantics | `library.txt` entries are user intent: offline paths load and persist instead of being filtered out at startup | Filtering on `Path::exists()` silently evicted every entry on an unplugged card, and the next library save made the eviction permanent | 2026-06-11 |
| Save-as-copy export location | Exports land in repo-local gitignored `edited/` (overwrite per source on re-export); legacy beside-the-source placement remains only as the no-repo-root fallback | The app must never write into source folders — they may be camera cards; `edited/` joins `decoded-cache/`/`local-edits/` in the 2026-06-10 runtime-directories caveat (move to `%LOCALAPPDATA%` before distribution), though unlike the caches its fallback keeps saves functional without a repo root | 2026-06-11 |
| Default RAW develop tone | Apply +1.0 EV + contrast 65 (the app's own darktable-style primitives, exact per-channel LUT) to full RAW develops in `decode.rs`, before caching; embedded previews/thumbnails keep the camera curve. Constants tuned by percentile-matching one real ARW's embedded preview (the reference look) via the env-gated tuning harness | rawler's develop has no tone curve and reads flat next to the camera JPEG and Lightroom; baking tone into the base keeps slider semantics and CPU/GPU parity untouched and costs one cached pass. Single-reference tuning is the documented v1 limitation; per-camera curves and color-profile matching are future work | 2026-06-12 |
| Default RAW develop tone — calibration (supersedes the single-reference constants above) | +0.85 EV + contrast 65, the aggregate optimum (best mean AND best worst-case luma-percentile distance) over 35 Sony ARWs spanning daylight and indoor scenes, scored against each photo's embedded camera preview by the harness's directory mode | One-photo tuning overfit (daylight scenes wanted less contrast, indoor scenes less exposure); optimizing mean + worst-case over a diverse set is robust without per-camera tables, which remain future work | 2026-06-12 |
| Session-state absorption detection | Completed persists report their written bake generation; the app records the latest per path and treats a reload that returns exactly that generation as having absorbed the session's edit state, resetting it (undo for that photo drops at that point) instead of re-applying. While a newer persist is still racing, the reload adopts that request's own retained base image rather than the stale disk bake, so unsaved newer state survives on the base it was authored on. Chosen over parametric edit persistence (Lightroom-sidecar model), which remains the structural successor if cross-session slider continuity is ever wanted | The bake advances with every commit while session slider state stays anchored to the loaded base; reloads after session-cache eviction crossed the two timelines and compounded edits into the bake (post-hoc finding 3-H1), and a reload racing an in-flight persist could otherwise wipe newer unsaved state (iteration-4 finding). Generation equality plus the racing request's retained base are together the smallest observables that separate "this reload contains my edits" from "this reload races my pending persist" | 2026-06-11 |
