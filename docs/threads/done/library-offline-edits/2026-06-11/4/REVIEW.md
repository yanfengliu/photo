# Review — library-offline-edits, 2026-06-11, iteration 4 (verification of the v0.2.4 absorption mechanism)

Reviewers: Gemini 3.1 Pro (plan mode) and Claude (fable-5, effort max, codebase-grounded), both on the pre-commit v0.2.4 diff. Claude's pass landed after the racing-substitution fix was already in the tree and verified the live code.

## Findings

| ID | Severity | Finding | Disposition |
|---|---|---|---|
| Gemini 4-1 | HIGH (as filed; real defect, severity overstated) | A reload racing a still-in-flight persist sees the older generation on disk, matches `last_completed_bakes`, and wipes the newer unsaved session state. | Real interleaving, fixed — but not via either of Gemini's suggested remedies (invalidate the generation record on queue, or gate the predicate on pending persists): both would make the reload keep the state and render it onto the stale bake, reintroducing the 3-H1 corruption. Actual fix: `newest_pending_persist_for_path` — the reload adopts the racing request's retained base (the pixels the state was authored on), keeping the state on its true anchor; no re-enqueue when the racing request already covers the visible state. The disk artifact was never at risk (the racing request holds the base `Arc` and its completion converges it). Gemini's claim that the older-generation regression test "simulates an impossible state" is wrong — a read racing an atomic rename delivers exactly that pairing; the test stands. Tests: `reload_racing_a_pending_persist_keeps_state_and_substitutes_the_pending_base`, `owed_fulfillment_defers_to_a_pending_persist_for_the_same_path`. |
| Claude 4-H1 | HIGH (regression introduced by the 3-M2 rider) | `owed_bake_has_nothing_new` treated "default state over a baked base" as a no-op unconditionally — but after a session persist advanced the disk past the loaded base, default is a REVERT that must bake. Undo-to-default on a baked photo silently kept the undone edit on disk (resurrected on restart), and the surviving redo stack could re-apply onto the absorbed bake, recreating the 3-H1 compounding corruption. | Fixed along the reviewer's direction: `loaded_base_generations` records each path's loaded-base generation; the predicate (now `bake_has_nothing_new`, a method) skips the identity bake only when no session persist exists or the last completed one still equals the loaded base, and never while a persist races. `reset_absorbed_session_state` now always replaces the history (stale redo dies with it). The fulfill path judges nothing-new against the stale decode's own context — its older base is exactly the right one to re-bake a revert from. Tests: `undo_to_default_on_a_baked_base_rebakes_the_revert`, `absorbed_reload_clears_stale_redo_state`. |
| Claude 4-M2 | MEDIUM | Commits made during the reload window (accepted while `blocks_save()`, no racing persist to carry them) were silently wiped by the absorbed reset; a failed persist could similarly leave history ahead of the recorded bake. | Fixed per the reviewer's hardening: completions record the persisted `EditState` alongside the generation (`CompletedBake`); an absorbed reset whose current state differs from the recorded baked state surfaces a status notice instead of discarding silently. Perfect recovery is not expressible under baked-pixel persistence (the anchor base is gone) — parametric persistence remains the recorded successor. Test: `absorbed_reload_with_unbaked_commits_resets_and_surfaces_a_notice`. |
| Claude 4-M3 | MEDIUM | The owed-arm racing guard deferred to ANY racing persist, including ones older than the owed state (reachable because owed commits happen under `blocks_save`), silently dropping the newer commit. | Fixed by mirroring the current-request arm: defer only when the racing state equals the current history; otherwise bake the newer state on the racing request's base. Existing defer test adjusted to model the equal-state case it was meant to pin. Test: `owed_fulfillment_overrides_an_older_racing_persist_with_the_newer_state`. |
| Claude 4-L4 | LOW | Docs lagged the tree (test counts, racing-substitution missing from ARCHITECTURE/decisions). | Fixed: changelog/devlog/ARCHITECTURE/decisions describe the substitution and the final counts. |

Claude explicitly verified as holding: reset ordering vs the session cache, generation lifecycle including the no-repo-root `None` case, generation-ABA being unreachable (time-XOR-nonce ids + atomic rename), and that each new test fails if its specific fix regresses.
