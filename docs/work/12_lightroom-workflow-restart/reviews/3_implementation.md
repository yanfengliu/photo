### Codex lane

I would not accept the claim that all seventeen defects are fixed. I reviewed `2ad1f0076d09d7e95bec0ecd3052de714ae326d9` statically. No files changed, no cargo commands ran, and test assessments below are from code rather than execution.

- **E1 — PARTLY FIXED. High.** At [place.rs:144](crates/export/src/place.rs:144), the identity check and replacement remain separate. Export A to B with Overwrite; move A onto B after `original.is(B)` returns false but before `rename`. The rename destroys the original. Holding its handle preserves its identity, but does not make replacement conditional on that identity. The direct placement test exercises the earlier move correctly and would fail with the old implementation. The integration test performs a real concurrent move, but neither targets this remaining window.

- **E2 — PARTLY FIXED. High.** Exclusive creation prevents two cooperating Skip/UniqueName exports from claiming the same free name. However, [place.rs:225](crates/export/src/place.rs:225) closes the reservation before replacement. Another process can rename a valuable file over that reservation; line 229 then overwrites it. On rename failure, cleanup identifies ownership only by “regular file, zero bytes,” so it can also delete somebody else’s replacement empty file. All four named tests are sequential: the “appeared” file already exists before the operation, and the two claimants run one after another. Their assertions would also pass with an equivalent exists-then-rename fallback. They do not establish race safety or behavior on an actual exFAT volume.

- **E3 — FIXED.** The comparison at [place.rs:60](crates/export/src/place.rs:60) uses retained file handles. I also inspected `same-file`’s Windows implementation: it compares volume and file index. Both named tests create actual hard links. They distinguish this repair from the old Windows implementation; passing them on Unix alone would not establish that distinction. Windows execution remains unchecked.

- **E4 — FIXED.** The [sanitizer test at naming.rs:210](crates/export/src/naming.rs:210) exercises the actual sanitizer with superscript names, case variants, extensions, and spaces before extensions. Restoring the old reserved-name list would fail it. This check does not require Windows filesystem execution.

- **G1 — PARTLY FIXED. High.** Available directory aliases are handled, but the unavailable-folder fallback still loses aliases. At [guard.rs:78](crates/engine/src/export/guard.rs:78), consider a catalog entry through `/photos/link`, pointing to an unavailable `/disk/actual`. `folder_key` cannot canonicalize the dangling link and compares the unresolved alias against the real destination; no original names are collected. Restore the drive before the export worker runs: exporting another photo to `/disk/actual/IMG.jpg` can overwrite the catalogued original because the guard retains that empty name set. Both named symlink tests are real and would fail under the old basename filter. The unavailable-folder test uses the same pathname on both sides and misses this variant.

- **G2 — FIXED.** The [reload condition at load.rs:150](crates/engine/src/develop/load.rs:150) preserves the draft when the catalog still contains its committed baseline. The named scenario actually imports photos, creates a virtual copy, removes it, and checks that the edit remains uncommitted before committing it. Removing the repair would lose the draft during that sequence.

- **G3 — PARTLY FIXED. Medium.** Ordering is per literal `PathBuf`, not per sidecar reached through aliases: [files.rs:40](crates/engine/src/sidecars/files.rs:40). Catalog the same image through `/real/a.jpg` and a directory symlink `/alias/a.jpg`; save older values through one record and newer values through the other. They receive different locks and counters, so the older save can still land last on the same physical sidecar. The unit test deterministically exercises reversed execution and would fail without the newest-ticket check, but it would still pass with the mutex removed because its writes never overlap. The engine stress test can pass without ordering when workers happen to finish in submission order. Normal ticket cleanup appears sound; the repair does not establish ordering against external writers or deletion.

- **G4 — FIXED.** Completion takes contrast from current settings at [quick.rs:215](crates/engine/src/quick.rs:215). The named test changes contrast before polling the automatic result, so worker scheduling cannot make the newer adjustment arrive after completion. Restoring whole-tone replacement would fail it.

- **G5 — FIXED.** [batch.rs:50](crates/engine/src/develop/batch.rs:50) restricts the preliminary commit to the affected open photo. The test exercises an actual drag, automatic work on another photo, and history length before and after release. Unconditional committing would fail it.

- **G6 — FIXED.** [tree.rs:129](crates/engine/src/undo/tree.rs:129) keeps a depended-on keyword in `Present` state, so redo reuses its ID rather than restoring a duplicate. The test performs a real sidecar import and checks that redo uses the same keyword. It would fail under unconditional deletion. Children are checked in the implementation, although the named test covers assignments only. Retained keywords can later become unused, but this does not create duplicates on repeated undo/redo.

- **G7 — PARTLY FIXED. Medium.** Ordinary destruction now records completed copies, including ready slots behind abandoned work. During panic unwinding, however, [engine.rs:452](crates/engine/src/engine.rs:452) returns before draining outcomes or recording ready slots. A published copy awaiting delivery remains unrecorded if an unrelated caller panic drops the engine. The named test covers ordinary drop, but does not force a published, unrecorded copy to exist at that moment; it can pass without the repair when only recorded copies exist and shutdown cancels the next copy. The catalog remains alive throughout the drain. Keeping already-copied files from cancelled imports follows the existing contract at [import/mod.rs:5](crates/engine/src/import/mod.rs:5).

- **G8 — PARTLY FIXED. Medium.** Disclosure is repaired; newer-settings protection is not. [import/files.rs:82](crates/engine/src/import/files.rs:82) still assigns `data.develop`, which is `None` for format 99. The catalog therefore receives ordinary editable defaults without the unreadable-format state. Import such a photo, dismiss the warning or reopen the application, then develop or export it: the engine accepts defaults instead of enforcing its newer-settings restriction. The named test would fail without the warning repair, but explicitly asserts defaults and never checks edit/export refusal or protection after reopening.

- **G9 — FIXED for the reported per-photo transaction loop.** The new batch uses the existing transaction boundary at [catalog.rs:173](crates/catalog/src/catalog.rs:173), outside the diff hunks. Its invalid-photo/keyword test changes an earlier entry before encountering the error and verifies rollback; a straightforward per-photo transaction implementation would fail it. Engine assignment undo/redo use that batch. Keyword creation still has separate transactions, so the entire command is not literally one transaction. The ignored 500-photo timing test does not count transactions and could pass either implementation on sufficiently fast storage.

- **G10 — FIXED for obsolete queued decodes.** Cancelled jobs are rejected before execution at [jobs/mod.rs:195](crates/engine/src/jobs/mod.rs:195); closed sessions also discard results of decodes still running when cancellation is observed. Already-running codec work remains non-interruptible. The named test checks cached decodes, and all six fixtures fit within the source-cache budget, so the old implementation would retain six and fail. Its “at most two” expectation is scheduling-sensitive: a descheduled calling thread could let more decodes finish between successive opens even with the repair.

- **G11 — PARTLY FIXED. Medium.** Cancellation after processing starts now stops the entry loop. Cancellation during [scan.rs:172](crates/engine/src/import/scan.rs:172) still waits for the entire directory enumeration and subsequent sort before reaching another check. A huge or slow network directory can therefore hold the worker—and shutdown—after cancellation. The named test starts cancellation only after enumeration is over. Moreover, retaining only the new cancellation check in `post`, while removing the entry-loop check, can satisfy its candidate-count assertion while enumeration/stat work continues through the remaining files.

- **G12 — FIXED for late deliveries.** The request boundaries at [frames.rs:143](crates/engine/src/develop/frames.rs:143) reject frames for abandoned choices. The Before test leaves a real request outstanding; the preset test deliberately injects an obsolete delivery into the actual acceptance path. Both would fail without their corresponding delivery checks. The same-choice early return introduces a separate regression described below.

- **G13 — PARTLY FIXED. Medium.** A preview loaded from disk while its original is offline returns no stamp at [job.rs:188](crates/engine/src/previews/job.rs:188). `remember_stamp` removes its stamp, and `recheck` immediately returns for unstamped entries. Reconnect the drive with a changed original: the memory preview remains stale indefinitely while retained. A RAW embedded interim preview followed by a full-render failure has a related problem: the memory hit precedes the failure/retry branch, so the full preview is never retried. The named tests cover neither case. They would distinguish the implemented retry/recheck paths from the old behavior, but replacing the intervals with zero does not validate the production timing or work bounds.

The repairs also introduce these defects:

- **NEW — E2, Medium: an unfinished export appears under its final name.** [place.rs:223](crates/export/src/place.rs:223) publishes a zero-byte `.jpg`/`.tif` reservation. A directory watcher can immediately consume it as an export. If the process stops before rename, it remains permanently; a later Skip export reports the name as already occupied. The tests cover successful rename and a clean failure, not interruption between reservation and publication.

- **NEW — G1, Medium: starting a local export can block on unrelated storage.** [guard.rs:72](crates/engine/src/export/guard.rs:72) opens every populated catalog folder synchronously. Its caller, [export/mod.rs:197](crates/engine/src/export/mod.rs:197), runs on the engine thread before returning a task. Export one local photo from a catalog containing thousands of folders on disconnected network storage: startup waits for those filesystem operations and fallback canonicalizations, freezing the engine before the export can be cancelled.

- **NEW — G3, Medium: cancelling the newest save suppresses an earlier uncancelled save.** At [files.rs:56](crates/engine/src/sidecars/files.rs:56), an older ticket skips solely because a newer ticket was claimed. With workers occupied, queue save S1, queue S2 for the same path, then cancel S2. S1 subsequently reports success without writing; S2 is skipped by the pool. Neither snapshot reaches disk, despite S1 remaining uncancelled. The counter has no mechanism to withdraw a cancelled successor.

- **NEW — G7, Medium: shutdown can spend minutes retrying an unavailable catalog.** Drop now reaches the batch fallback at [import/run.rs:313](crates/engine/src/import/run.rs:313). Suppose 100 published copies await recording and another connection holds the catalog’s write lock. The batch fails, then each photo is retried separately. The inspected rusqlite version installs a [five-second busy timeout](rusqlite-0.43.0/src/inner_connection.rs:90), permitting roughly 505 seconds of blocking for that batch alone. There is no shutdown deadline or distinction between a bad individual photo and a database-wide failure.

- **NEW — G12, Medium: repeating a preset request cannot recover a request made before loading.** Call `preview_preset(A)` before the source is decoded; rendering does nothing, but the choice is stored. After decoding, call it again with the same size and settings. [tools.rs:153](crates/engine/src/develop/tools.rs:153) now returns immediately. The unchanged [source-loaded path at load.rs:274](crates/engine/src/develop/load.rs:274) requests Main, Before and Overlay, but never Look. No preset frame arrives until the choice changes. Previously the repeated call would render it. The named test starts with loading already complete.

- **NEW — G13, Medium: source rechecks can accumulate without bound and occupy every worker.** [recheck.rs:55](crates/engine/src/previews/recheck.rs:55) updates the timestamp when submitting an unkeyed job, without tracking whether an earlier recheck remains queued or running. Keep requesting cached thumbnails while their source share stalls: every two seconds another job per requested entry enters the unbounded background queue at [jobs/queue.rs:55](crates/engine/src/jobs/queue.rs:55). Running metadata calls can occupy all workers, delaying urgent decodes and blocking shutdown’s joins. This is demand-driven, not a sweep of every cached preview, but neither the pixel budget nor `STAMPS_KEPT` bounds these jobs. The five-second failed-preview retry has per-key in-flight suppression; the two-second rechecks do not.
