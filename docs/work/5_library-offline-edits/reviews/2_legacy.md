Verdict on the landed work: **all four iteration-1 fixes verified correctly landed** — the owed map is leak-free (every registered entry receives exactly one `ImageLoaded`), the stale-preview rescue cannot duplicate decodes (a stale preview can only belong to a request whose full task was never spawned), fail-closed semantics and the exports change have no regressions, and the H1 regression test correctly de-masks the helper pre-seeding.

## Findings

| ID | Severity | Finding | Disposition |
|---|---|---|---|
| Claude 3-H1 | HIGH (pre-existing, found by auditing the H1 invariant beyond the diff) | Editing on top of an existing bake corrupts on any in-session disk reload: commit S over baked base B1 → persist writes B2 = render(B1, S) while the session keeps state S and base map `PersistedLocalEdit` → evict from the 4-entry session cache (browse 4+ photos) → reopen loads **B2** from disk → Detail renders S on top (visible double-apply) and the unconditional post-load persist re-bakes render(B2, S), compounding per revisit. Open on both the mainline and owed paths; v0.2.2's fix only covered decodes whose base was `Original`. | Fixed in v0.2.4: completed persists report their written generation (`CompletedLocalEditBake`); the app tracks `last_baked_generations` per path; a reload whose `bake_generation` matches is recognized as having absorbed the session state — the state resets (image unchanged, undo dropped per the session-only contract) and nothing re-persists. A generation mismatch (reload racing an in-flight persist) keeps the state, preserving the previously-correct behavior. Applied to the current-request arm and owed fulfillment. Tests: `reload_of_a_bake_that_absorbed_the_session_edits_resets_history_instead_of_reapplying`, `reload_of_an_older_bake_keeps_session_state_while_the_newer_persist_is_pending`, `owed_fulfillment_skips_when_the_loaded_bake_already_absorbed_the_state`. |
| Claude 3-M2 | MEDIUM (pre-existing) | The mainline current-request arm still performed full-resolution identity re-bakes for unedited baked images on every fresh-from-disk open (M3 only fixed the owed path), including a spurious warning per open when the source is offline (the bake write needs source metadata). | Fixed in v0.2.4: `current_local_edit_persist_request` now uses the same `owed_bake_has_nothing_new` predicate (the pending-reset case — default state + `Original` base + existing bake — still persists and removes). Test: `reopening_an_unedited_baked_image_does_not_rebake_identical_pixels`. |
| Claude 3-L3 | LOW (residual, disclosed in iterations 1–2) | The M2 rescue chain line has no failing test: reverting it passes the suite because the regression test hand-delivers the chained `ImageLoaded`. | Accepted (iced `Task` is opaque); both prior REVIEW.md files disclose it. Extracting a pure chain-vs-drop decision function remains an optional follow-up. |
| Claude 3-L4 | LOW | `owed_bake_skipped_for_unedited_baked_image` was described in iterations 1–2 as the fulfillment-guard test, but the registration guard skips first, so the fulfillment-time guard and its seed-before-skip ordering were untested; the prior REVIEW.md evidence lines are inaccurate on this point (left as-is — done threads are historical artifacts; corrected here). | Fixed in v0.2.4: `owed_fulfillment_guard_skips_after_state_reset_but_still_seeds_base_source` registers with a real commit, resets the state before the stale decode lands, and asserts the skip plus the base-map seed. |

## Outcome

The landed commits hold; the pass's value was finding 3-H1 — the corruption class was closed for `Original`-base decodes but open for bake-as-base reloads. v0.2.4 closes it with generation-tagged absorption detection. Process lesson recorded in `docs/learning/lessons.md`: fixing an invariant for the path in the diff without auditing the sibling paths that share the invariant leaves the same failure class open — audit the invariant, not the diff.
