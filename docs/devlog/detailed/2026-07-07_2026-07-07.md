# Devlog 2026-07-07 — 2026-07-07

## 2026-07-07 23:45 — Agent harness (v0.2.8): drive the app like a user, observe like an instrument

**Action.** Built the agent harness end to end, modeled on civ-engine's visual-playtest + recursive-improvement principles (surveyed from its 1.3.0–1.6.0 changelog arc and `docs/threads/current/agent-recursive-improvement-loop/DESIGN.md`): stable app-owned contract, player-level action vocabulary through real dispatch paths, dual visual+mechanical observation, replayable run artifacts, findings-as-claims. New modules: `src/launch.rs` (CLI parsing + process-wide options), `src/harness/{mod,run,server,stats}.rs` (protocol types, run manifest/session info/UTC-id/token helpers, token-gated JSON-lines TCP server as an iced subscription, pure pixel statistics), `src/app/{harness_exec,harness_actions,harness_observe,harness_artifacts}.rs` (dispatcher, user-equivalent actions, observation/controls builders, screenshot/dump/stats/compare/manifest pipelines), `src/bin/harnessctl.rs` (std-only client), runtime storage-sandbox overrides in `library.rs`/`repo.rs`, and `save_in_flight` tracking in the app. Thread: `docs/threads/current/agent-harness/` (DESIGN.md, PLAN.md). Guide: `docs/guides/agent-harness.md`. AGENTS.md gained an "Agent harness" section wiring it into the visual-change verification rule.

**Motivation (user-stated pain).** Slider-tuning development was bottlenecked on the human relaying "the edited photo still looks weird" (value-range issues, tuning-algorithm differences vs reference looks). The harness closes that loop: the agent sees the true GPU frame (`iced::window::screenshot` — verified in vendored iced_wgpu source to include custom shader primitives, then spiked live before building on it), measures the CPU render (percentiles/clipping/histogram/saturation at full resolution), and iterates.

**Design decisions.** (1) In-app control channel over OS-level automation or test-only message driving: the real app, real render loop, real message dispatch, but deterministic and replayable; civ-engine's browser adapters synthesize protocol-level events the same way. (2) Sandbox-by-default storage via runtime `OnceLock` overrides — extends the v0.2.7 test-isolation lesson to harness runs; `--harness-real-storage` opts out. (3) Action responses mean "gesture performed", with `wait_idle` as the explicit synchronization point (loads, EXIF, persists, saves). (4) Findings/manifest contracts documented (schema v1 in the guide), enforcement-by-code deferred exactly as civ-engine did 1.4.0→1.6.0. (5) No new crate dependencies; tokio gained `net`/`io-util`/`sync`/`time`/`macros` features only; `harnessctl` is std+serde_json. (6) No `docs/api-reference.md` was created: the protocol reference's single source of truth is the guide — a second copy would only drift (the doc-discipline checklist's api-reference item is satisfied by the guide for this binary crate).

**Implementation notes.** Slider drag semantics reproduced exactly (two `SliderChanged` + `SliderReleased`; first change is drag-detection); the double-click-reset affordance is deliberately defused for consecutive harness drags by clearing `last_slider_release` (pinned by test — a real trap: two rapid `set_slider` calls on the same kind would otherwise reset the slider to 0). Keys route through `handle_key` (the only thing `handle_event`'s keyboard arm does); `set_crop` emits the same committed-crop viewer event a drag produces and requires crop mode like a user; dialog-opening controls (`add_folder`, ctrl+o) are refused with pointers to `import_files`/`import_folder`/`open` (the dialog-completion messages — the post-dialog user path). Screenshot/dump/stats run on blocking threads; artifact paths are run-dir-relative; `tokio::time::sleep` futures are wrapped in lazy async blocks so unit tests without a reactor can drop tasks unpolled. wait_idle uses a deduped 100 ms poll chain with per-request deadlines.

**Found-by-harness fix.** The first live session exposed that `wait_idle` didn't cover the async save task (agent saves → immediately reads the export → race). Fixed with `save_in_flight` on `App` (set in `SaveEdited`, cleared in `SaveCompleted`), included in the idle condition and the pending report, with a regression test. This is the improvement loop eating its own dogfood on day one.

**Dependency-change protocol (tokio feature addition).** `cargo update` (minimal, per-package: tokio 1.50→1.52.3, + tokio-macros) then `cargo audit` — which surfaced five vulnerabilities that predated this work (advisories published after the 2026-06-13 baseline): quick-xml 0.37 (RUSTSEC-2026-0194/0195, both 7.5 HIGH, DoS vectors) as a direct dependency, again transitively at 0.39, and crossbeam-epoch (RUSTSEC-2026-0204). Fixed the direct tree: quick-xml → 0.41.0 (the Lensfun parser migrated off removed `BytesText::unescape` onto the 0.40+ model where entity references arrive as separate `GeneralRef` events — text now accumulates per element and resolves numeric + predefined-entity references; all lens tests pass), crossbeam-epoch → 0.9.20. The remaining pair lives only in `wayland-scanner`, a Linux-only build-time proc-macro pinned to quick-xml ^0.39 upstream — never compiled on this Windows-targeted app, parses trusted in-tree protocol XML; suppressed in `.cargo/audit.toml` with reason and a 2026-10-01 re-check expiry. `cargo audit`: clean (0 errors, 11 default-tolerated unmaintained/unsound warnings, unchanged class from the June baseline).

**Reviewer findings (2026-07-08, two iterations; full synthesis in `docs/threads/done/agent-harness/2026-07-08/{1,2}/REVIEW.md`).** In-process adversarial Workflow (5 finder dimensions x refuting verifiers; 9/13 agents completed before the Claude session-quota limit killed 4) + Codex CLI; Claude CLI unreachable on the same quota per the unreachable-CLI protocol. By theme — *Workflow, concurrency (CONFIRMED medium, fixed):* stale async completions (screenshot/dump/stats) could be delivered to the NEXT client connection after a timeout/Ctrl-C and, with harnessctl's per-connection ids restarting at 1, be silently accepted as the answer to a different command — exactly the wrong-feedback failure the harness exists to prevent; fixed with a connection-generation counter threaded through all async completions (stale ones dropped, artifacts still recorded), pinned by test, re-smoked live over four reconnections. *Workflow, sandbox (CONFIRMED HIGH, fixed):* decode.rs's private duplicate of repo-root discovery ignored the harness sandbox override, so sandboxed sessions read/wrote/pruned the REAL `decoded-cache/` — the exact landmine the 2026-06-10 "dedup is a tracked follow-up" note deferred; fixed by delegating decode.rs resolution to `crate::repo` (failing-first test), closing the tracked follow-up. *Workflow, refuted:* a prepare_runtime partial-failure claim was demonstrated unreachable by its verifier — the refuting-verifier stage paying for itself in both directions. *Workflow, unverified but hardened:* import_files now rejects paths no real dialog could produce; click now refuses controls whose `enabled` is false via the same predicate the observe list reports (synthetic tab controls removed). *Codex, docs:* DESIGN.md still described the drafted command vocabulary (`which:`, `toggle_crop`, dedicated zoom/nav commands) — rewritten to the as-shipped contract with the fold-into-`key`/`click` rationale.
