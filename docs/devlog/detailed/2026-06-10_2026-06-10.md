## 2026-06-10 14:10 — CI flake fix: same-size rewrite vs mtime granularity (commit H, v0.1.6)

- Action: CI run 27305008375 failed on `decode::tests::cached_full_image_redocodes_when_source_file_changes` (left: 1, right: 2 — the rewrite was never detected) while the same suite passed locally all day. Root cause: the test rewrites `<svg>A</svg>` → `<svg>B</svg>` (same byte length), so invalidation depends entirely on the mtime changing, and the persisted cache's metadata fast path is designed to treat same-size+same-mtime as unchanged; the v0.1.4 optimized-dependency speedup made the CI runner fast enough to land both writes inside one Windows file-time tick. Fix: a `rewrite_with_distinct_mtime` test helper that rewrites and verifies the mtime advanced (bounded retry with 15ms sleeps), used at the rewrite site, plus a regression test for the helper itself. Audited the other same-size rewrite sites: the fingerprint test at decode.rs compares content hashes directly (mtime-independent) and the session cache always content-verifies after its metadata check, so no other test carries the assumption.
- Reviewer comments: n/a — CI-caught regression fixed under the same thread; the iteration-1 REVIEW.md disposition stands.
- Result: All four gates green; 299 tests pass (was 298; the helper regression adds one).
- Reasoning: The production fast path is a documented, intentional tradeoff (lessons 2026-04-20), so the fix belongs in the test, which must assert the contract "redecode when the change is observable through metadata," not "redecode on any write."
- Notes: This is the exact class of latent assumption that only surfaces when something else gets faster — recorded in lessons.md with anchors.
