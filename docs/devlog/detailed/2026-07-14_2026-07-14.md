## 2026-07-14 04:25 — RAW conversion is downscale-only (v0.2.9)

**Action.** While establishing the supplied-photo baseline for natural edit-range tuning, closed a verified prerequisite defect in `raw_dynamic_image_to_rgba`: image 0.25's `DynamicImage::thumbnail` enlarges inputs when the requested box is larger, but the helper called it unconditionally with the 16384 GPU limit for full RAW conversion. The helper now calls `thumbnail` only when an axis exceeds the requested bound, then applies orientation as before. `DECODE_CACHE_CONTRACT_VERSION` moved 6→7 so cached accidental upscales rebuild once; the cache schema and user-authored `local-edits/` files are unchanged.

**TDD and result.** The red regression passed a 2×1 image through a bound of 10 and reproduced a 10×5 result. The fix preserves 2×1 and the exact two source colors. Review-driven coverage now also pins embedded-preview orientation at 2×1→1×2 and full RAW develop orientation at 24×12→12×24 while retaining exact rotated-pixel comparisons. All 60 decode tests pass. Live harness run `20260714-111324Z-14504` opened the same `DSC01839.ARW` used by the earlier finding: the previous run reported a 16384×10923 pixel buffer, while the fixed run reports 9504×6336 (and full-render statistics at 9504×6336) against the unchanged 9728×6656 logical sensor dimensions. The run was sandboxed, waited idle, captured GPU/CPU evidence, finalized with `quit`, and left no owned process behind.

**Reviewer comments.** In-process finder/refuter `raw_no_upscale_refute` verified the image 0.25.10 resize semantics, cache read/write boundary, orientation ordering, and historical cache versions against the live code. It found one MEDIUM test blind spot: the old orientation tests compared two outputs that had both been accidentally upscaled, so agreement did not prove correct dimensions. Exact normal/rotated dimensions were added for embedded previews and full develops, then the reviewer re-read the final diff and reported no substantive issue. Its remaining naming/comment nits were also resolved. Review synthesis: `docs/threads/current/natural-edit-ranges/2026-07-14/1/REVIEW.md`.

**Reasoning.** Broad RAW self-play would otherwise render and cache roughly three times the necessary pixels and could bias performance observations. Fixing the conversion boundary before range calibration keeps the private fixtures at their real developed resolution without changing any slider math or UI range.
